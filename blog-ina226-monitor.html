从硬件工程师视角：用 INA226 做一个 0.1% 精度的电能监测仪

Deng Wenbo · Hardware Design · ~5 min read

毕业后我独立完成了一个小型硬件项目——基于 STM32 与 INA226 的便携式电能监测仪。这篇文章复盘选型、设计与实现的全过程。

为什么做这个项目

本科期间我做了 SMPS 开关电源设计仿真，但始终缺少"真实硬件测量"的环节。 电压到底是多少？电流消耗多大？效率是否真的到了 75%？ 这些问题让我决定做一个能实时测量电压/电流/功率/电能的小工具。

核心选型：为什么是 INA226 而不是 ACS712？

方案 原理 精度 适用场景
ACS712 霍尔效应 较差 (±1.5%) 大电流粗略测量
采样电阻 + 运放 差分放大 中等 需要外部设计
INA226 分流电阻 + 19-bit ADC 0.1% 电源监测标准方案

INA226 是 TI 推出的电流/电压/功率监测芯片，采用分流电阻方案，内部集成了 19-bit ΔΣ ADC。 关键在于它的 总线电压采样（直接接 VIN+ 和 VBUS），通过内部计算寄存器 可以直接读出功率和电能，极大简化了固件工作量。

硬件设计要点

1. 引脚分配

  • I2C1: PB6 (SCL), PB7 (SDA)，挂载 INA226 (0x40) 和 OLED (0x3C)
  • USART1: PA9 (TX)，输出串口数据
  • 按键: PA0，切换显示页面

2. 开尔文连接（Kelvin sensing）

这是本项目最重要的一个设计细节。分流电阻 Rshunt 两端如果直接用一根粗线采样，铜箔电阻会引起测量误差。正确做法是：

主电流路径：VIN+ ──→ Rshunt ──→ VIN-
采样路径：Kelvin+ ──→ ADC ──→ Kelvin-

两路分开走线，采样线不流过主电流，从根本上消除了 PCB 走线电阻误差。

3. 固件架构

main.c        # 主逻辑：周期采样 + 刷新UI + 串口输出
ina226.c/h    # 芯片驱动：寄存器读写、校准、数据解析
oled.c/h      # SSD1306 驱动：缓冲显存 + 局部刷新
ui.c/h        # 4页面交互：电压/电流/功率/电能

INA226 校准流程（关键代码）

校准的本质是设置电流分辨率 Current_LSB，使其与实际量程匹配：

const float current_lsb = MAX_CURRENT / 32768.0f;  // 2.0A / 32768 = 61uA/bit
uint16_t calib = (uint16_t)(0.00512f / (current_lsb * RSHUNT));
// 0.00512 是 INA226 内部校准常数
INA226_WriteReg(REG_CALIB, calib);

校准完成后，读电流寄存器直接乘以 LSB 就是安培数，读功率寄存器乘以 25×LSB 就是瓦特数。

测试结果

项目 结果
电压精度 (3.3V-12V 全量程)< 0.3%
电流精度 (22mA-100mA)< 2%
功率计算< 2%
电能累计 (10分钟连续)< 3%

总结

这个项目让我把大学的理论知识真正落地：

  1. 理解了专用电流检测芯片 vs 通用 ADC 的本质区别
  2. 掌握了开尔文四线测量的工程实践
  3. 完成了原理图 → PCB → 固件 → 测试的完整闭环
