// Overview

Developed an autonomous obstacle-avoidance robot based on ARM Cortex-M4F (MSP432P401R) using C. Part 1 implements bare-metal interrupt-driven control with 6 collision switches; Part 2 integrates FreeRTOS with 6 concurrent tasks, mutex-protected shared data, and 1ms system tick scheduling.

基于 ARM Cortex-M4F 微控制器的自主避障机器人，实现裸机中断与 RTOS 多任务两套架构对比。

// Bare Metal vs RTOS Comparison

Aspect Part 1: Bare Metal Part 2: FreeRTOS
Program Structure while(1) + ISR Tasks + Scheduler
Concurrency ISR preempts main loop Priority + time-slice switching
Responsiveness Immediate (ISR) Depends on priority/scheduling
Shared Data volatile keyword Mutex protection
Complexity Low Higher (race/deadlock)

Key insight: bare-metal "super-loop + ISR" suits simple systems; RTOS adds task abstraction and deterministic scheduling at the cost of synchronization management.

// Technical Highlights

1. P4->IV Interrupt Vector

Used the P4IV hardware interrupt vector register to resolve multi-pin priority races in the ISR. When multiple switches trigger simultaneously, hardware arbitrates and returns the highest-priority pending pin: 

// P4IV = 2 × (pin + 1) · hardware auto-clears IFG
status = P4->IV;  // 0x02=Pin0, 0x06=Pin2, ..., 0x10=Pin7
switch(status) {
    case 0x02: /* Bump1 → action */ break;
    case 0x06: /* Bump2 → action */ break;
    /* ... up to 0x10 */
}

2. Mutex-Protected Shared Data

Three tasks concurrently access the global variable bumpSwitch_status. Protected with FreeRTOS mutex — which provides priority inheritance, mitigating priority inversion: 

SemaphoreHandle_t xBumpMutex = xSemaphoreCreateMutex();

// Writer task
if( xSemaphoreTake(xBumpMutex, portMAX_DELAY) ) {
    bumpSwitch_status = Bump_Read_Input();
    xSemaphoreGive(xBumpMutex);
}

/* Reader tasks: Take → Read → Give */

3. FreeRTOS Design

/* 6 tasks · 5-level priority · 1000Hz tick */
- taskT (priority 2): master control (suspend/resume via SW2)
- taskBumpSwitch (priority 1): collision detection
- taskdcMotor (priority 1): motor control
- taskMusic (priority 1): buzzer playback
- taskInput (priority 1): key input
- taskDisplayOutputLED (priority 1): LED display
