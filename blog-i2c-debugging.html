嵌入式开发实战：STM32 驱动 INA226 的 I2C 通信踩坑记录

Deng Wenbo · Embedded · Debugging · ~6 min read

在电能监测仪项目中，与 INA226 的 I2C 通信让我踩了不少坑。这篇记录解决问题的过程，希望帮后来者少走弯路。

遇到的三个问题

问题1：I2C 总线被锁死

现象：上电后读 INA226 返回值全是 0x0000，OLED 同时无响应。

排查过程：

  1. 先测 OLED 地址 0x3C——正常
  2. 再测 INA226 地址 0x40——无 ACK
  3. 用逻辑分析仪看波形，发现 SDA 一直为低

根因：INA226 模块板载的上拉电阻与 STM32 内部上拉冲突，导致总线被拉死。

解决：把 STM32 对应引脚的内部上拉关闭（改开漏 + 外部上拉）， 或移除模块板上一个上拉电阻。

问题2：Device ID 读不到

现象：读 REG_DEVICE_ID (0xFF) 返回 0x0000。

根因：我犯了个低级错误——忘记左移 1 位。 INA226 的 7-bit 地址是 0x40，但在 HAL 库中 I2C 地址需要左移一位 （0x40 << 1），因为 HAL 内部会自动处理 R/W 位。 

// 错误
#define INA226_ADDR 0x40
// 正确
#define INA226_ADDR (0x40 << 1)

问题3：电压值跳动 ±50mV

现象：读数在 4.95V ~ 5.05V 之间波动。

分析：

  1. INA226 默认平均次数为 1，对噪声敏感
  2. 采样线过长，引入了干扰

解决：

  1. 将 CONFIG 寄存器的平均次数设为 1024 次
  2. 把采样线尽量缩短、并联 0.1uF 滤波电容
/* 1024次平均, 连续双通道采样, 5.12ms */
#define INA226_CONFIG_DEFAULT 0x07FF
INA226_WriteReg(REG_CONFIG, INA226_CONFIG_DEFAULT);

平均后电压波动减小到 ±1mV 以内。

经验总结

  1. 地址移位：任何 I2C 从机接入 HAL 库，都要记得把 7-bit 地址左移 1 位
  2. 上拉电阻冲突：模块自带上拉的场景，注意与 MCU 内部上拉的匹配
  3. 片内平均滤波：24-bit 测量芯片通常内置平均功能，善用可以极大提升稳定性
  4. 排查工具：逻辑分析仪（¥25 的 8 通道版就够用）是调试 I2C 的神器

附：调试代码片段

/* 探测I2C设备 */
uint8_t buf;
HAL_I2C_Mem_Read(&hi2c1, (0x40 << 1), 0xFF,
                 I2C_MEMADD_SIZE_8BIT, &buf, 1, 100);

/* 快速验证：写配置后读回比对 */
INA226_WriteReg(REG_CONFIG, 0x07FF);
uint16_t back = INA226_ReadReg(REG_CONFIG);
printf("Config: 0x%04X\r\n", back);
